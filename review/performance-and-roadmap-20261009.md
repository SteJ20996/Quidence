# Quidence：大量記錄測試與數學地圖方案

2026-10-09。程式碼基線為 GitHub main 對應的當前發布樹；測試在獨立本機瀏覽器及本機伺服器執行，沒有向正式網站傳送壓力流量。效能優化已在工作區完成；數學地圖為互動預覽，尚未接入正式首頁。

## 測到了什麼

測試資料由現有基礎測試引擎生成：每次包含 15 道題、原始解釋、提交歷史、題目定義和派生報告。解釋包含英語、西班牙語和中文，核對儲存、重載和切換語言後原文不變。資料是合成樣本，不能用來驗證教學效果。

| 條件 | 結果 |
| --- | --- |
| 100 個並行本機 HTTP 請求，分 5 批，共 500 次 | 0 次失敗；優化版 P95 158.4ms。只表示這次本機測試，不是 Cloudflare 的容量證明。 |
| 8 個獨立瀏覽器上下文同時造訪首頁、診斷與報告 | 頁面與儲存成功；重載後各自記錄獨立。 |
| 10 / 100 / 250 次完整測試記錄 | 歷史完整；最後的未提交輸入可以重載恢復。250 次檔案約 296 萬字元。 |
| 10 / 50 份完整報告 | 所有報告可造訪；分頁不會刪除記錄；新儲存不會改變舊報告正文。50 份檔案約 303 萬字元。 |
| 100 份本次結構的報告 | 此瀏覽器的儲存空間不足，無法植入這組資料。沒有把這個條件算作通過。報告容量取決於實際文字、繪圖與版本數量。 |
| 空間耗盡後儲存新報告 | 明確報告失敗；已有檔案逐字不變。 |
| 同一活動在兩個標籤頁中編輯 | 後一個過期標籤頁停止寫入並提示衝突；第一個草稿保留，第二個標籤頁的草稿可單獨下載。 |

## 找到並修復的瓶頸

原來每次鍵盤輸入都同步序列化並重寫整個答題檔案。現在連續輸入合併儲存，停止輸入約 150ms 後寫入；失去焦點、提交、切換活動、隱藏頁面及正常離開頁面時同步儲存。瀏覽器異常退出發生在這段短視窗內時，最後少量輸入仍可能未落盤。此機制不能替代持久儲存。

報告讀取去掉了一次不必要的完整深複製；新增報告只遷移舊格式的指紋，不再重新計算所有當前指紋。是否增加版本仍比較真實記錄，不能因指紋碰撞而跳過不同答案。日期格式器按語言複用。報告列表按最後儲存時間排列，每頁 20 條，所有歷史版本仍保留；新增文字已有西班牙語翻譯。

| 同樣的本機條件 | 優化前 | 優化後 |
| --- | ---: | ---: |
| 250 次記錄，連續輸入 100 個字元，正常 CPU | 5.53 秒 | 0.10 秒 |
| 250 次記錄，連續輸入 100 個字元，CPU 限速 4 倍 | 20.41 秒 | 0.30 秒 |
| 50 份報告，讀取檔案，CPU 限速 4 倍 | 86ms | 25ms |
| 50 份報告，儲存新報告，CPU 限速 4 倍 | 304ms | 234ms |

時間包含測試工具的操作開銷，會受機器狀態影響；CPU 限速只是較慢裝置的代理，不能代表真實 iPhone 或安卓手機。大檔案初次恢復仍有可察覺的短暫停頓：250 次記錄、限速 4 倍時重載約 615ms，觀察到的最長主執行緒任務約 272ms。結果是降低卡頓，並非保證任何裝置永不卡頓。

完整迴歸通過：npm test；28 項針對檔案、原始證據、容量失敗及語言的檢查；瀏覽器 80 個活動頁面 / 40 個草稿恢復流程；西班牙語 33 節課 / 132 個步驟 / 956 個控制項狀態。地圖在 320、375、736px 檢查了節點選擇、語言切換、未來內容說明、Logo 載入和橫向溢出，均通過。

可復現：設定可用的 `QUIDENCE_BROWSER_EXECUTABLE` 後執行 `npm run test:history:stress`。原始結果在同目錄的 performance-baseline-20261009.json 與 performance-optimized-20261009.json。

## 數學地圖怎麼放

建議首頁保留當前直接選課功能，在課程選擇附近加入一個簡版路線和“Explore the mathematics map”入口；完整地圖使用單獨頁面。地圖先幫助學生看懂知識關係，點選節點後再顯示這部分學什麼、與哪些內容相連，以及現有課程、測試和專題的入口。行動裝置改成縱向排列，避免縮小一張桌面大圖。

地圖使用“建立基礎 → 連接思想 → 應用方向”三個區域。預代數、代數 I、代數 II、預微積分、微積分構成常見路線；幾何與代數互相支援，統計及線性代數保留並行分支。物理連結目前的兩門基礎課程；經濟學與更高階數學顯示為未來探索，不能讓學生誤以為已經有完整課程。地圖展示相關概念的聯繫，而不是唯一的學習順序或課程解鎖條件。

設計參考現有課程目錄，以及 [Common Core 的函數與建模說明](https://www.thecorestandards.org/Math/Content/HSF/) 和 [Illustrative Mathematics 的代數 I 路線](https://tasks.illustrativemathematics.org/blueprints/A1)。節點、文字、圖形和產品版面為本專題方案，沒有複製第三方課程材料。

目前預覽只顯示選擇狀態，不虛構學生等級或掌握率。正式接入後可先顯示可核對的事實，例如“開啟過”“提交過答案”“有待複查的具體題目”。後續再根據多次表現和人工複核，為某個錯誤模式提供下一步建議；代數困難時可推薦有關的幾何表示，保留所依據的題目和教學變化。

## 後續優先順序

1. 在真實手機上覆測當前版本，尤其是報告開啟、鍵盤輸入、繪圖及後台恢復。
2. 長期學習記錄遷移到按活動分開的 IndexedDB 儲存，配置可見的容量提示、備份與原有檔案遷移。當前 localStorage 的空間限制已經被實際測到；不應靠刪除舊學習證據來解決。
3. 經確認後接入數學地圖及課程入口；再接入有證據的學習記錄狀態。
4. 增加實際頁面效能與錯誤觀測，用真實慢操作和失敗率判斷何時需要進一步優化。上線容量需要獨立、有限度的環境測試；造訪統計中的累計請求數不能替代並行或效能測量。

當前靜態資源由 Cloudflare 分發。其[靜態資源計費與限制文件](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)說明靜態資源請求免費且數量不限；這不代表前端計算、瀏覽器儲存或未來資料庫及 AI 介面也沒有瓶頸。
