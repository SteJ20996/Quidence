# A steady logo while pages load · 2026-11-01

Opening a page made the logo jump once or twice. Sometimes it also showed briefly in a color that blended into the header. A recording of every released page in all four appearances found three causes. All three are fixed.

## Causes

1. **The page was pushed down after it was painted.**
   - What is inserted:
     - The records banner ("New learning records stay in this browser").
     - The appearance bar.
     - On 13 pages, the language menu row.
   - When: scripts inserted these at the top of the page only after all deferred scripts had run, which is after the page was first painted.
   - Effect: the logo and everything below it dropped by about 120 px, once or twice.
2. **The logo was painted in the wrong color, then swapped.**
   - Each page's HTML starts with the dark-ink logo. In Classic, most headers are dark teal, so the logo first appeared almost invisible.
   - `themes.js` then swapped it for the white logo, which reloaded the image.
3. **Coordinate Geometry replaced its logo, and its Intuition Lab card was placed above the header.**
   - The app rebuilt the header on every view and fetched the logo again.
   - The card was briefly placed above the header, then moved under it.

## Fix

- **Bar, banner and language row arrive with the page.**
  - `assets/themes.js` inserts them as soon as `<body>` exists, before anything is painted.
  - `assets/local-records.js` now only corrects the banner's text if browser saving turns out to be unavailable.
  - `assets/i18n.js` takes over the language row instead of building a new one. When it has to build one, it places it under the appearance bar, which keeps the original order: banner, appearance bar, language menu.
  - When a page's own header holds the language menu, the early row is removed as soon as that header is parsed. This applies to course pages and the Intuition Lab.
  - The appearance bar starts in the language the page is about to use.
- **The logo color is chosen before it is painted.**
  - `themes.js` picks the logo in the frame before the logo's first paint, once the page's styles have loaded. Pages that insert a logo later get the same treatment.
  - While the other logo loads, a browser keeps showing the old image. So the logo stays hidden until the right one has loaded, instead of showing on the wrong background.
  - In Classic, the white logo starts loading at high priority as soon as a logo is parsed, because most Classic headers are dark. A recording on a slow connection (120 ms latency, 200 KB/s) shows the white logo 3 to 9 ms after the first frame of the page. Before, the near-invisible dark logo showed for over a second, then the page dropped, then the logo turned white.
- **Coordinate Geometry keeps its logo.**
  - The app moves the existing logo into each new header instead of creating a new one.
  - `assets/intuition-links.js` places the Intuition Lab card under the app's header from the start.

## Measurements

Every released page and the homepage course view, in all four appearances, on the local server. Layout shift is the browser's own measure, CLS; below 0.1 counts as good.

| | Before | After |
| --- | --- | --- |
| English, 1280 px: average layout shift while loading | 0.169 | 0.036 |
| English, 1280 px: page loads with layout shift above 0.05 | 91 of 140 | 34 of 140 |
| English, 1440 px: page loads where the logo moves after the first paint | 56 | 0 |
| Spanish, 375 px: average layout shift while loading | 0.530 | 0.182 |
| Logo swapped after the first paint (Spanish, 375 px) | 16 | 0 |

The final contrast between the logo and the pixels behind it is at least 10:1 on every page in every appearance. The same holds after switching appearance.

## Not changed

- **Caching.** The live site serves every asset with `cache-control: no-cache`, including fingerprinted files such as `quidence-logo-dark.svg?v=…`. So a browser asks the server again for each one on every page view. Fingerprinted files could be cached for a year, but some files are also loaded without a fingerprint, so the rule needs care. It is left for a separate change.

- **Shifts in page content.** Some shifts below the header remain. The logo does not move in these cases.
  - The Intuition Lab card is added under the header after load, for example on Discrete Mathematics.
  - Some apps rearrange their own content after rendering: the Math Voice Lab and the Linear Algebra matrix page.
- **Spanish pages.** In Spanish, pages are still drawn in English first and translated once `i18n.js` and its catalog load. Longer Spanish labels can wrap onto more lines, so on phones the logo can still move down once. This was already the case and is much smaller than before, but it needs pages delivered in Spanish to remove completely.

## Checking

`scripts/load-stability-probe.cjs` records the logo while a page loads. `npm run test:themes:browser` runs it on every released page in every appearance:
- **At 320 px (Spanish) and 1440 px (English):** it fails if the logo is swapped after the page was painted.
- **In English only:** it also fails if the logo moves more than 8 px after the first paint. A few pixels can come from a web font arriving.

Against main, the same check finds 56 page loads where the logo moves; with this change it finds none.
